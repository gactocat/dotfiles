`{BRIEF}` を読んで、その指示どおりに一次調査を進めてください。

これは無人の一次調査です (`claude -p`)。人に質問はできず、権限の確認が要る操作は拒否されます。拒否された操作は無理に回り道をせず、報告書の「できなかったこと」に書いてください。判断が要るところは、選択肢と推奨と理由を報告書に書いて先に進みます。

## 終わり方

- 結論、根拠、事実と推測の区別、人が判断・実行すること、返信の文案を `{REPORT}` に書いたら終わる。調査が途中でも、使える予算や時間が尽きる前に、そこまでの結果で書く
- 最後の応答は、報告書のパスと 3 行の要約だけにする

## AWS

- `aws-perman-auth` skill の手順で認証を確かめる。macOS に `timeout` は無いので、`perl -e 'alarm 300; exec @ARGV' aws --profile <プロファイル> sts get-caller-identity` の形で呼ぶ
- 認証が切れていて CIBA (Slack での承認) が発火したら、待つのは 1 回だけ (最大 5 分)。承認されなければ AWS を使わずに進め、報告書に「AWS で確かめること」を書く。同じタスクで CIBA を何度も発火させない
- 本番は読むだけ。SQS の receive-message のように読むだけでも状態が変わる操作はしない

## してはいけないこと

- Slack への投稿、リアクション、下書き。assigner の操作 (close、assign、priority など)。返信は報告書の文案まで
- GitHub への書き込み (コメント、PR、Issue、ラベル、push)
- AWS、GCP、PERMAN、Kubernetes の変更。Terraform の apply
- Orca の操作、worktree の削除、自動化の設定の変更
- 秘密の値 (トークン、パスワード) を報告書や memory に書くこと

これらは hook でも止めています。止められたら、文案や手順として報告書に書いてください。
