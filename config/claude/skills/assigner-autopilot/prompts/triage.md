## 手順

1. `mcp__claude_ai_Slack__slack_read_thread` で、channel_id と message_ts (task_id の `#` の後ろ) のスレッドを読む (response_format は "detailed")。添付の画像やファイルがあれば `mcp__claude_ai_Slack__slack_read_file` で中身を見る (依頼が短い文と画像だけのことが多い)。依頼者の名前は `mcp__claude_ai_Slack__slack_read_user_profile` で確かめてよい。人名の漢字は推測で書かない
2. 手がかりのファイルがあれば読む: {KNOWLEDGE}
3. 下の基準で 3 つに分ける
4. investigate か question なら、ブリーフの本文を書く

## 分け方

| class | 目安 |
| --- | --- |
| investigate | エラー、動かない、見られない、データの食い違い、費用の急増、アラートなど、ログ・コード・データを見ないと答えられない |
| question | 使い方、仕様、手順、権限の申請の案内など、文書とコードを読めば答えられる |
| human | 承認、判断、日程、評価や人事、PR のレビュー依頼、cc だけ、雑談、ほかの担当者がスレッドで動いている、本人がすでに中身のある返信をしている、秘密情報 (パスワード、トークン、個人の連絡先の一覧など) が含まれる |

- 迷ったら human にする
- #mam-alert-prd のアラートも、ほかのチャンネルと同じ基準で分ける。MAM Monitor (巡回) の報告がスレッドにあれば、手がかりとして使う
- 依頼者が本人のタスク (自分用のメモ) は human にする
- reason に、そう分けた根拠を 1〜2 文で書く。other_assignee_active と self_replied も埋める

## ブリーフの本文 (brief_body)

調べるセッションはこの会話を知らない。次の 3 つの見出しで Markdown を書く (見出しは `##`、番号を付けない)。「注意」と「成果物」はあとで機械的に足すので書かない。

- `## 背景`: Slack のリンク (url)、channel_id と ts、依頼者、依頼の日時、優先度と最初の返信の期限、担当者、スレッドの要点 (依頼の本文の要点と、それまでのやり取り)
- `## 手がかり`: 関係しそうなもの (memory の索引にある名前、手がかりのファイル、Issue や PR、リソースの ID やパス)。無理に挙げない
- `## やること`: 調べることを順に (番号付きリスト)、出してほしい判断材料、返信の文案の宛先と型

## 書き方

日本語。和文と英数字のあいだに半角スペース、見出しに番号を付けない、区切り線を使わない、絵文字を使わない。title は 20 文字くらいまでの日本語の短い名前で、依頼の中身が分かるもの (例「素材の容量表示のずれ」)。summary は 2〜3 文。
