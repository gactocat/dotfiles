# esa の収集

esa MCP ツールを使う。未ロードなら ToolSearch で `esa_list_posts`, `esa_get_post`, `esa_list_comments` をロードする。**esa MCP は認証切れになりやすい**。ツールが認証エラーになったら、ユーザーに claude.ai のコネクタ設定 (またはインタラクティブセッションの /mcp) で esa を認証し直すよう依頼する。認証を待つか esa をスキップするかはユーザーに選んでもらう。

## 検索

esa の検索クエリ構文が使える:

```
user:<screen_name> created:><開始日> created:<<終了日>
```

新規作成と更新を分けて取る:

- 新規: `user:<screen_name> created:><開始日> created:<<終了日>`
- 更新 (期間内に手を入れた既存記事): `user:<screen_name> updated:><開始日> updated:<<終了日>` から新規分を除く

## 見るもの

- 記事の種類の分類: 設計書 / 障害報告 (ポストモーテム) / 定例議事録 / 手順書 / 調査記録
- 注目記事 2〜5 件を `esa_get_post` で読む。選ぶ基準: 設計判断を含む、障害対応の記録、他チームからも参照されそうな手順書、star や watch が多い
- コメントでの他者との議論があれば `esa_list_comments` で確認する

## 注意

- `user:` で拾えるのは記事の作成者・更新者としての活動。**他人の記事へのコメント**は検索で拾いにくい。注目記事のコメント欄で見かけたら evidence に加える程度でよい。
- 定例議事録のような当番制の記事は成果というより運用貢献。定量サマリでは区別して数える。
