# Slack の収集

Slack MCP ツールを使う。未ロードなら ToolSearch で `slack_search_users`, `slack_search_public_and_private`, `slack_read_thread` あたりをまとめてロードする。

検索は実行者 (マネージャー) のアカウント権限で行われるため、実行者が参加している private チャンネルも含まれる。DM は対象にしない (収集しても本人との信頼を損なうだけで考課の材料にならない)。

## 発言の収集

基本クエリ:

```
from:<@UXXXXXXXX> after:<開始日前日> before:<終了日翌日>
```

after/before は排他的なので前後 1 日ずらす。結果が多い場合はチャンネルやキーワードで分割する:

- `from:<@U...> in:#<主要チャンネル> after:... before:...` — チャンネル別の活動量
- `from:<@U...> "障害" after:...`、`"リリース"`、`"設計"` など仕事の種類を表すキーワードで絞る

全メッセージを読むのではなく、次を把握する:

- **どのチャンネルで多く発言しているか** (活動の場の傾向)
- **注目スレッド 3〜5 件**: 障害対応をリードした、技術的な解説をした、意思決定を促した、チーム外からの問い合わせに答えた、などのスレッド。`slack_read_thread` で文脈を読み、permalink を記録する

## 他者支援の観点

本人発のメッセージだけでなく、**他人のスレッドへの返信**が支援の evidence になる。検索結果でスレッド返信 (thread_ts が親と異なるもの) に注目し、質問者への回答・レビュー依頼への応答・トラブル時の駆けつけを拾う。

## 注意

- Slack 検索は網羅的でない (インデックスの都合で取りこぼしがある)。件数は「傾向」として書き、厳密な数値として扱わない。
- 発言数の多寡それ自体は評価に直結しない。数より「どんな場面で頼られているか」を読み取る。
- レポートに引用する場合は要旨に留め、必ず permalink を付ける。
