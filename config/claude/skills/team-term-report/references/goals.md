# 期初の目標設定の受け取り

Priority 欄は期初に握った目標の**転記**である。したがって振り返り資料の作成は、必ず目標設定の入力から始める。入力がないまま推測で Priority を書くと、資料全体が査定に使えなくなる。

## 受け取り方

次のいずれかでユーザーから受け取る。どれも得られない場合は、作業を止めて入力を依頼する。

- 本文の貼り付け (最も確実)
- ローカルファイルのパス
- esa の記事 URL (`esa_get_post`) / Google Docs・スプレッドシート (`read_file_content`) / Notion ページ (`notion-fetch`)。これらの MCP ツールは ToolSearch でロードしてから呼ぶ。esa MCP は認証切れのことがあるため、失敗したら本文の貼り付けを依頼する
- 前期の振り返り資料 (`~/Documents/term-reviews/`) の Priority 欄。ただし前期のものである可能性が高いので、今期の内容かをユーザーに確認する

目標設定シートの所在が分からない場合は、メンバー名と期を手がかりに esa・Drive・Notion を検索してよいが、**見つけたものを勝手に採用しない**。候補を提示し、どれが正しいかをユーザーに確認する。目標設定の取り違えは資料全体を無効にする。

## 拾う項目

| 項目 | 用途 | 欠けている場合 |
| --- | --- | --- |
| Objective と KR の番号・タイトル (`O1-KR1: ...`) | 資料の見出し | 番号体系をユーザーに確認する |
| KR ごとの P0 / P1 / P2 の記述 | `[Priority]` 欄への転記 | 期初に未設定なら `未定義` と書く。取得漏れなら再度依頼する |
| キャリアラダーの対象等級 (例: 専門性 JB06) | キャリアラダー節の見出し | ユーザーに確認する |
| 期初に置いたキャリアラダーのアクション | 同節の Action の起点 | 実績から構成し、期初設定がなかった旨を添える |

P0 / P1 / P2 は達成率の目安と対応する。

| Priority | 達成率の目安 |
| --- | --- |
| P0 | 80% |
| P1 | 100% |
| P2 | 120% |

## 取り込み後

取り込んだ目標設定を作業ファイル (スクラッチパッド、または資料と同じディレクトリの作業メモ) に保存し、以降の突き合わせと転記はそこを参照する。会話の要約で失われても再取得しなくて済む。

保存する内容:

- KR 番号とタイトル
- KR ごとの P0 / P1 / P2 の原文 (要約せず原文のまま。転記のため)
- キャリアラダーの等級と期初アクション
- 出典 (URL またはパス)。資料の作成根拠として残す

要約や言い換えをせず原文を保持すること。Priority 欄は転記であり、言い換えると期初に何を握ったかが分からなくなる。
